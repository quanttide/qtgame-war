# 意图系统

## 设计目标

意图系统解决的不是"玩家选一个标签"，而是**玩家的判断自动折射为立场，立场决定他能看到什么选项**。

理想状态下，玩家不会觉得自己在"选意图"。他做判断、下决定，系统从决定中识别他的意图。意图是指挥官决策的自然产物，不是操作入口。

## 现状与理想差距

### 现状（HTML 原型）

- 玩家点三个按钮之一，面板切换
- 本质是选项卡切换，跟"立场决定视野"有一层隔阂
- 消耗是抽象数字 +1，没有具体含义

### 理想状态

**1. 意图是判断的结果，不是选择的入口**

玩家面对的是情报面板和局势描述。他做出判断（"我必须先稳住局势"）后，系统自动将判断映射为意图。玩家不需要知道"我选的是积极防御"——他只知道"我决定先构筑工事迎击"。意图标签是系统反馈给他的，不是他操作的入口。

**2. 不同战役的决策起点不同，选择逻辑也不同**

- 帝丘店开局：玩家收到"邱清泉 3 天后到"的情报。他的注意力自然放在"抢时间"。系统从"抢时间"推断意图为积极防御。
- 开封开局：玩家看到"40 万居民未疏散"。他的注意力自然放在平民。系统从关心平民推断意图为保护平民。
- 豫东第一阶段开局：玩家看到"敌军番号不明"。他的注意力自然是侦察。系统推断意图为收集情报。

这三个开局的操作是不一样的——不是"从三个里选一个"，而是"对当前最紧迫的问题做出反应，系统映射为意图"。

**3. 消耗有具体含义**

切换意图不是扣一个抽象点数。消耗体现在：
- 时间：命令传递需要时间，部队调动方向要重来
- 组织成本：各级指挥员刚理解上一个意图，又要重新调整
- 信息失效：在改意图期间，旧情报可能已经过时

消耗不一定是"惩罚"。粟裕在豫东改了四次意图，每次改变都是对局势的更优判断。消耗的意义是让玩家意识到"改变决心是有重量的"，不是随便点一下。

## 实现路径

当前原型（HTML 单页面）验证了"行动面板随意图过滤"这个基本机制。理想状态需要等 Flutter 建模阶段实现，届时：

1. 情报系统（Phase 2.1）先跑起来——玩家看到的是情报，不是意图按钮
2. 意图系统（Phase 2.2）接收情报判断的结果，而不是接收按钮点击
3. 消耗与战场时间线绑定，不是抽象数字
