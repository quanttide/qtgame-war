# 意图系统路线图

> 概念设计见 `docs/intention/index.md`。本文件只列实现任务，不重复设计理由。

## Phase A — 原型验证（已完成）

- [x] HTML 单页面原型：意图选择 → 面板过滤 → 叙事变体 → 切换代价 → 重置
- [x] 战役预设初始意图（campaign.json `initial_intent` 字段）
- [x] 三个战役示例：帝丘店（积极防御）、开封（保护平民）、豫东第一阶段（收集情报）

## Phase B — 概念确认

将理想设计与当前技术栈对上，确定 Flutter 实现方案。

### B1 接口定义

- [ ] 定义 `Intent` 模型：值（enum）、可用行动映射表、叙事模板引用
- [ ] 定义意图与情报系统的接口：IntelGenerator 输出 → 意图影响叙事文本
- [ ] 定义意图与命令系统的接口：意图影响 Command 可用性
- [ ] 定义意图与后果系统的接口：切换意图触发消耗事件

### B2 战役配置扩展

- [ ] 在 `campaign.json` 中定义 `initial_intent` 字段规范
- [ ] 在 `campaign.json` 中定义意图→行动映射表（覆盖 JSON，允许战役覆盖默认）
- [ ] 验证：换个战役是否只改 JSON、不改 Dart 就能换意图配置

### B3 设计评审

- [ ] 对比原型与理想设计的差距（见 `docs/intention/index.md`），确定 Phase C 的实现范围
- [ ] 决策：Phase C 是继续做"选意图"交互，还是直接做"从情报推断意图"

## Phase C — Flutter 实现

### C1 意图模型和状态管理

- [ ] 创建 `Intent` 枚举（protect / defend / scout / ...）
- [ ] 创建意图→行动映射表（可配置化，战役可覆盖）
- [ ] 创建 `CommanderState`（或纳入 `GameState`）：当前意图、切换次数、意图历史
- [ ] 意图切换方法：参数为新意图 → 校验 → 触发后果事件 → 更新状态

### C2 意图切换后果

- [ ] 切换消耗与战场时间线绑定（不是抽象数字）
- [ ] 消耗的具体表现：时间推进、情报时效增加、部队疲劳
- [ ] 长冷却后果：短时间内多次切换，消耗递增

### C3 意图驱动的行动面板

- [ ] 行动面板根据当前意图渲染对应选项（if-else 渲染分支，不是 disable）
- [ ] 禁止选项直接消失
- [ ] 顶部意图指示器持续可见
- [ ] 行动选项与兵棋引擎的 Command 对接

### C4 意图影响叙事

- [ ] 情报文本根据当前意图选择变体（对齐 QA C07）
- [ ] 叙事模板配置化（intent→场景→文本模板，战役可覆盖）
- [ ] 与 IntelGenerator 对接：同一基础情报 × 不同意图 = 不同措辞

### C5 从情报推断意图（理想态）

> 此阶段为可选，取决于 B3 评审结论。

- [ ] 定义"局势→意图"映射规则
- [ ] 情报看板 + 局势描述 → 自动推断意图
- [ ] 玩家不直接点意图按钮，而是通过决策行为体现立场
- [ ] 意图标签作为系统反馈展示给玩家
