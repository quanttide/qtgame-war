豫东样本 · 核心机制版
一句话定位
玩家下决心，引擎用史实参数裁决，玩家撞的墙就是区寿年撞过的墙。 样本不是胜负计算器，是“对比器”——机制成立的唯一标准：玩家的失误点与史实指挥员的失误点能否重合。
三个核心机制（其余全部砍掉）
机制一：兵力比裁决（唯一的核心公式）
有效兵力比 = 玩家投入兵力 ÷（敌军账面兵力 × 指挥可用度系数）
• 三纵合围 → 约 1:1.6 → 合围成立
• 两纵合围 → 约 1:1.1 → 合围不稳，突围概率升
玩家的一切胜负感都从这一个比值来。指挥可用度 0.6–0.8 允许扰动——扰动 ±30% 后三纵结论仍稳、两纵结论翻转，这既是玩法深度，也是引擎要的第一个敏感性结论，一个机制双份产出。
机制二：机动力查表（只留两档）
	轻装	重装
干路	快	慢
黄泛区/暴雨	中	几乎停滞
裁决值全部取区间中值，相对比例先不较真。机制的存在价值就一条：玩家把重炮派进黄泛区，一回合就会懂；史实里华野也是这么懂的。
机制三：事件触发器（只有两条，全部来自史实）
• 6/26 前未拉开邱区间隙 → 邱清泉回援，兵力比翻转，合围破裂（区寿年的墙）
• 拖延至 6/29 后才合围 → 黄百韬解围（拖延者的墙）
玩家的失败不是被扣分，是撞上史实里真实存在的那堵墙——这是样本的灵魂，也是“历史已测过失真率”的机制化。
时窗与胜利条件（各一条）
• 7 天回合制（6/25–7/2），每回合 12 小时，俘补率 0.5–0.7 造成可战兵力逐日递减，第七天逼近极限——时间压力本身即机制，不需要额外规则；
• 胜利条件一条：华野方 7/2 前克龙王店且战损 <40%；区方撑到援军。就这两句。
验收测试（唯一的一条）
AI 按史实决策链行动时，玩家复现得了史实合围；玩家主动犯错时，AI 复现得了史实突围。双向跑通即成立，跑不通改表不改方法论。
