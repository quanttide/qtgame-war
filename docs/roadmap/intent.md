## Phase C — Flutter 实现

### C1 意图模型和状态管理

- [ ] 创建 `Intent` 枚举（protect / defend / scout / ...）
- [ ] 创建意图→行动映射表（可配置化，战役可覆盖）
- [ ] 创建 `CommanderState`（或纳入 `GameState`）：当前意图、切换次数、意图历史
- [ ] 意图切换方法：参数为新意图 → 校验 → 触发后果事件 → 更新状态

### C2 意图切换后果

- [ ] 切换消耗与战场时间线绑定（不是抽象数字）
- [ ] 消耗的具体表现：时间推进、情报时效增加、部队疲劳
- [ ] 长冷却后果：短时间内多次切换，消耗递增

### C3 意图驱动的行动面板

- [ ] 行动面板根据当前意图渲染对应选项（if-else 渲染分支，不是 disable）
- [ ] 禁止选项直接消失
- [ ] 顶部意图指示器持续可见
- [ ] 行动选项与兵棋引擎的 Command 对接

### C4 意图影响叙事

- [ ] 情报文本根据当前意图选择变体（对齐 QA C07）
- [ ] 叙事模板配置化（intent→场景→文本模板，战役可覆盖）
- [ ] 与 IntelGenerator 对接：同一基础情报 × 不同意图 = 不同措辞

### C5 从情报推断意图（参谋长模式，理想态）

> 此阶段为可选，取决于 B3 评审结论。对应"选项 A"。

- [ ] 定义"情报质量阈值→参谋长建议"映射规则
  - 情报清晰时：参谋长的建议符合战役逻辑（如帝丘店→建议积极防御）
  - 情报模糊/矛盾时：参谋长建议"先收集情报"
  - 情报误导时：参谋长可能给出错误建议——这正是指挥官（玩家）发挥判断力的空间
- [ ] 情报系统输出 → 参谋长分析（LLM 或规则） → 玩家看到参谋长的建议
- [ ] 玩家通过决策行为体现立场（不直接点意图按钮）
- [ ] 系统从玩家决策中识别意图，意图标签作为反馈展示
- [ ] 角色对：**参谋长**（分析建议，不做决策）←→ **指挥官**（阅读情报，听取建议，最终决策）
- [ ] 验证：参谋长建议不是权威，不是"提示系统"，而是世界的一部分——指挥所里参谋分享专业分析
