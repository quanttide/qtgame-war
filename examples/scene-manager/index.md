# 剧本管理工具对齐记录

记录 scene-manager 的方向共识与待决问题。人类确认一项，就关闭一项。

## 定位

- 服务对象：人类作者与 AI 协作，管理反事实推演剧本（if 线）从产生到可用的全流程
- 解决的痛点：现有 if 线剧本是 AI 对话导出的自由长文，缺少统一结构，难以比较、检索、追踪推演进度
- 明确不做：AI 推演本身、战棋系统、服务端。这是管理工具，不是推演引擎

## 数据模型（默认方案）

剧本为 Markdown 文件，YAML frontmatter 承载元数据，正文按 `docs/dev-guide/method.md` 五步组织：

```markdown
---
battle: 豫东战役
status: draft | verified | playable
focal_points: []   # 支点清单
variants: []       # 反事实变量
outcomes: []       # 结局 + 概率
---
```

## 形态与数据模型（2026-09-06 定稿）

- 形态：`scene_manager.py`，tkinter GUI，零安装依赖（Python 标准库 + PyYAML）
- 数据源：`scenes/*.md`，frontmatter 承载元数据，正文按 `docs/dev-guide/method.md` 五步组织（原文原样保留，不改写）
- schema 简化：outcomes 用扁字符串「结局名（NN%）」承载概率，不用嵌套对象，便于免解析器读写
- 状态枚举扩充：`scanned`（支点已扫描未推演）→ `draft`（推演完成）→ `verified` → `playable`
- 功能：清单浏览、详情展示（含概率条与归一校验提示）、状态流转、新建脚手架、打开原文

## 流程约定

- 先交付垂直切片：1 个剧本按新格式整理 + 1 个可运行的最小工具，验收后再扩展
- 数据与代码分离：剧本是 Markdown 数据，工具代码不含战役内容
- 结构性改动超过 2 个文件先确认方向
- 本文档同时作为决策日志，重要结论回写此处
