# 参谋长模式 vs 极简模式 — 对比记录

> 实验 2.3 输出文件。在同场景下记录两个模式的差异，供 B3 设计评审决策参考。

---

## 两条路径在同一场景中的差异

测试场景：帝丘店战役（基准）——黄百韬被围，邱清泉驰援

### 选项 A（参谋长模式）

玩家经历：
1. 看到情报面板：`黄百韬收缩，邱清泉 3 天后到`
2. 参谋长分析框：`建议积极防御，构筑阵地迎击援军`
3. 玩家决策：点"构筑工事"按钮（不是点意图按钮）
4. 系统反馈：`你的决策表明你的意图是积极防御`
5. 切换：第二次决策点"派出侦察"，系统显示`意图切换 + 时间推进 + 情报时效磨损`

**玩家感受**：我在做指挥决策，系统在分析我的意图。

### 选项 B（极简模式）

玩家经历：
1. 看到意图按钮面板：`🛡️ 保护平民 / ⚡ 积极防御 / 🕵️ 收集情报`
2. 战役预设已亮起"积极防御"
3. 玩家点"积极防御" → 行动面板出现"构筑工事"和"出击"
4. 想切换 → 点"收集情报" → 行动面板切换
5. 消耗提示：`切换意图，消耗 +1`

**玩家感受**：我在选意图标签，然后看行动面板变化。

## 对比维度

| 评估维度 | 选项 A（参谋长模式） | 选项 B（极简模式） |
|---------|-------------------|------------------|
| **实现成本** | 高。需要：情报系统（情报模型+生成器+看板）、参谋长分析逻辑（LLM 或规则引擎）、UI 四区布局（情报/分析/行动/反馈）、意图推断逻辑（从行动反推意图）、切换成本绑定战场时间线。 | 低。在现有原型上扩展即可。核心是 Intent enum + action map + UI 渲染分支。数据走 JSON 配置，不需情报系统就绪。 |
| **交互复杂度** | 中。玩家流程：看情报 → 看参谋长建议 → 点行动按钮 → 看意图反馈。4 步闭环。 | 低。玩家流程：点意图标签 → 看行动面板变化。2 步闭环。 |
| **沉浸感** | 高。设计师、参谋长、指挥官三个角色自然存在。玩家觉得自己在指挥所里。 | 低。类似游戏设置菜单选择。 |
| **对情报系统的依赖** | 强。没有情报系统，参谋长无输入可分析，玩家无情报可看。情报系统是前置依赖。 | 弱。可以跑在兵棋引擎之上，或在原型阶段独立运行。情报系统不是前置依赖。 |
| **迭代风险** | 低风险但高投入。方向正确（与设计目标一致），但做一半可能被情报系统进度卡住。 | 低风险低投入。先跑通意图过滤的基本功能，后续迭代到参谋长模式。 |
| **玩家学习成本** | 中。需要理解"不直接选意图"的交互范式：行动按钮=决策入口，意图标签=系统反馈。可能有预期落差。 | 低。意图按钮+面板变化符合主流策略游戏的操作预期。零学习成本。 |
| **独特价值** | 意图是判断的副产品，不是操作入口——这是核心设计目标的直接实现。参谋长的存在让"情报迷雾"有了意义。 | 无独特价值。只是将"意图过滤"的技术验证转化为可运行的代码。参谋长模式的价值无法通过极简模式体验。 |
| **评审风险** | 如果评审后否定，投入全白费。 | 如果评审后否定，"至少跑通了基本功能"。 |

## 关键决策依据

### 选 A（参谋长模式）的前提条件

1. ❓ **情报系统（Phase 2.1）必须已经上线或即将上线**。没有情报系统，参谋长没有输入，做不成。
2. ❓ **团队愿意在"前情提要"上下功夫**。玩家第一次进游戏需要理解为什么参谋长的分析框不是提示系统。
3. ❓ **愿意接受"做了但可能不对"的风险**。参谋长模式的交互范式没有成熟游戏的先例，玩家的接受度未知。

### 选 B（极简模式）的前提条件

1. ❓ **做 B 是否等于否定了核心设计目标**？"意图是判断的副产品，不是操作入口"——极简模式恰恰把意图做成了操作入口。
2. ❓ **从 B 迭代到 A 的迁移成本**。B 模式下玩家习惯了"点意图标签"，切换到 A 模式时玩家需要重新学习交互范式。
3. ❓ **B 模式上线后，团队还会花时间做 A 模式吗**。B 模式"能用"，但"能用"不等于"实现了设计目标"。
