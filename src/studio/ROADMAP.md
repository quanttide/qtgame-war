# studio ROADMAP

## 核心机制（不变的目标）

**玩家是指挥官，不是棋手。** 每回合面对真实作战矛盾，下一个决心；决心被翻译成对各纵队的命令；战棋引擎用真实战术保真度（位置、地形、走位都算数）执行命令，把后果反馈回来，形成下一个矛盾。战棋是指挥官决策的后果引擎，指挥官层是战棋的决策接口。

龙王店原型第一次把这个机制接成整体，但没有真正的战斗在底下（地图是装饰、单位不动）；studio 旧引擎有真正的战斗，但没有指挥官层在上面（玩家逐子微操，是棋手不是指挥官）。**v0.1.0 的任务是把两者各留一半，接通中间那座桥。**

## v0.1.0 — 整合竖切（证明桥能通）

**目标**：跑通一条完整链路，证明核心机制成立：

> 真实矛盾 → 选一张决心卡 → 翻译成各纵队的真实移动/攻击命令 → 引擎执行真实机动 → 位置/地形结算 → 战报与新态势 → 下一个矛盾

**验收**：不再是「与原型逐机制等价」。验收标准是——玩家全程不逐子微操，只做指挥官级决策；引擎执行时位置与地形真实影响后果；一回合闭环可重复推进。原型的决策冲突（卡互斥、攻城/阻援两难、疲劳代价）在此成立即可。

### 分层结构（两层桥）

```
指挥官层（原型留下）   决心卡 + Task 档位 —— 「1纵这回合围困」这个姿态
        ↓ 翻译层（本版核心，= CommandExecutor）
执行层（引擎留下）     Command（带坐标/时限/目标）→ 移动/攻击序列
        ↓
   战棋引擎按位置结算，反馈战报与新态势
```

- **Task**（已建 `lib/models/task.dart`）是指挥官层词汇：描述一个纵队本回合的姿态，不含坐标。
- **Command** 是执行层载体：由翻译层从 Task + 战场态势推导出带坐标/目标/时限的指令，喂给引擎。
- 旧引擎的 `clickHex` 路径不删，降级为 CommandExecutor 的下游（引擎执行指令，不再接收玩家点击）。

### 工作面

**1. 翻译层 CommandExecutor（本版核心，新）**
- [ ] Command 模型：目标纵队、目标坐标/目标、行动类型、时限、状态
- [ ] Task → Command 翻译：把「围困/强攻/阻援」等姿态 + 当前战场态势，推导为该纵队的真实移动与攻击目标
- [ ] 引擎执行接口：把 Command 序列交给现有 GameController 执行（复用走子/结算，不复用玩家点击）

**2. 战场与剧本（最小可玩，取自原型+引擎）**
- [ ] 龙王店地图：六角格 + 地名（龙王店[要塞]、铁佛寺、帝丘店、田花园、杨拐），真实可走位
- [ ] 华野 4 纵队（1/4/6纵[assault]、11纵[reserve]）+ 守军（工事）+ 整25师（逐回合推进）
- [ ] 单位真实机动：位置/地形影响攻防与推进后果

**3. 指挥官决策层（取自原型）**
- [ ] 逐回合矛盾从战局派生（援军距离 / 疲劳 / 工事值），不写死 turn 脚本
- [ ] 决心卡：2–3 互斥方案，点卡 = 给一组纵队各指派一个 Task
- [ ] Task 微调：点算子在其可用档位间循环（`slotsFor` 已就绪）

**4. 反馈层**
- [ ] 结算 → 战报（位置/地形/掷骰可见）→ 新态势 → 下一个矛盾
- [ ] 胜负：克据点 / 部队失去战斗力 / 时限未决

### 明确淘汰（本版不做，避免回到旧范式）

- **原型的静态地图与不动单位**：位置必须变成真的，地图不再是装饰
- **原型的批量抽象 d6 结算**：无视位置，被引擎的位置结算取代
- **原型写死的逐回合卡脚本**（`cardFor()` 按 turn 分支）：卡从状态派生，这是机制不是剧本
- **旧引擎的逐子微操交互**（`clickHex` 玩家点击）：降级为引擎执行指令的内部路径
- **旧引擎的死情报/计划装饰面板**：不在此版重建
