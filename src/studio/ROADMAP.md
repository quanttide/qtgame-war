# studio ROADMAP

## 核心机制（不变的目标）

**玩家是指挥官，不是棋手。** 每回合面对真实作战矛盾，下一个决心；决心被翻译成对各纵队的命令；战棋引擎用真实战术保真度（位置、地形、走位都算数）执行命令，把后果反馈回来，形成下一个矛盾。战棋是指挥官决策的后果引擎，指挥官层是战棋的决策接口。

龙王店原型第一次把这个机制接成整体，但没有真正的战斗在底下（地图是装饰、单位不动）；studio 旧引擎有真正的战斗，但没有指挥官层在上面（玩家逐子微操，是棋手不是指挥官）。**v0.1.x 的任务是把两者各留一半，接通中间那座桥。**

## 架构约束（贯穿 v0.1.x）

- **不改造帝丘店引擎为通用引擎（B 路线）**：帝丘店引擎从设计起就未考虑多剧本，多处场景耦合（见下）。v0.1.x 只为龙王店写一条**轻执行路径**，仅复用真正通用的两块——六角几何（`hexDistance`/`getNeighbors`/`pixelToHex`）与战斗数学（命中/地形修正算法）。龙王店自带状态、胜负、地形名、单位字段，不塞进帝丘店的 `Campaign`/`checkVictory`/`Battlefield`。帝丘店引擎原样保留为独立模式。
- **已知地雷：红蓝语义相反**。studio `Side.blue` = 华野 = 玩家方，`Side.red` = 国军；而龙王店原型与中文战棋惯例均是红方 = 我方。移植时显式核对敌我，防「敌我颠倒」级错误。
- **根问题：执行原语私有且被点击态门控**。`_executeMove`/`_executeAttack` 是私有，且须先经 `selectUnit` 建立的 UI 状态（`selectedUnitId`/`moveCandidates`/`attackCandidates`）才生效——领域逻辑与表现层交互状态焊死。这是「引擎能否被命令驱动」的根，v0.1.0 必先解。

## v0.1.0 — 整合竖切（证明桥能通）

**目标**：跑通一条完整链路，证明核心机制成立：

> 真实矛盾 → 选一张决心卡 → 翻译成各纵队的真实移动/攻击命令 → 引擎执行真实机动 → 位置/地形结算 → 战报与新态势 → 下一个矛盾

**验收**：玩家全程不逐子微操，只做指挥官级决策；引擎执行时位置与地形真实影响后果；一回合闭环可重复推进。原型的决策冲突（卡互斥、攻城/阻援两难、疲劳代价）在此成立即可。

### 分层结构（两层桥）

```
指挥官层（原型留下）   决心卡 + Task 档位 —— 「1纵这回合围困」这个姿态
        ↓ 翻译层（Command + translator，已建）
执行层                  Command（带坐标/目标/时限）→ 轻执行路径 → 移动/攻击结算
        ↓
   位置/地形结算，反馈战报与新态势
```

### 已交付（桥的上半 + 输出端）

- **Task**（`lib/models/task.dart` + 测试 + `doc/models/task.md`）：指挥官层姿态词汇，七档命令 + 角色档位 + 疲劳规则，与原型等价。
- **Command + 翻译层**（`lib/models/command.dart` + `lib/controllers/command_translator.dart` + 测试 + `doc/models/command.md`）：把 Task + 战场态势具体化为带坐标的指令。纯函数，不掷骰不改状态。

### 待做（执行端，v0.1.0 剩余）

**1. 解根问题：抽公开领域执行口子**
- [ ] `applyMove(unit, to)` / `applyAttack(attacker, defender)`：公开、各自拥有不变量、返回战报，不依赖点击态
- [ ] 现有帝丘店点击路径退化为「算候选格 → 调同一对方法」的薄适配器（增量，不砸现有测试）
- [ ] CommandExecutor：把 Command 序列喂给这对口子执行，产出 Dispatch 战报

**2. 龙王店最小战场（自带，不塞帝丘店模型）**
- [ ] 六角地图 8×7 + 地名（龙王店[要塞]、铁佛寺、帝丘店、田花园、杨拐），复用几何库，可走位
- [ ] 华野 4 纵队（1/4/6纵[assault]、11纵[reserve]）+ 守军（工事）+ 整25师；单位自带 `task`/`fat` 字段（给 Task 一个家）
- [ ] 位置/地形影响攻防与推进后果

**3. 指挥官决策层**
- [ ] 逐回合矛盾从战局派生（援军距离 / 疲劳 / 工事值），不写死 turn 脚本
- [ ] 决心卡：2–3 互斥方案，点卡 = 给一组纵队各指派一个 Task（喂给翻译层）
- [ ] Task 微调：点算子在其可用档位间循环（`slotsFor` 已就绪）

**4. 反馈层**
- [ ] 结算 → 战报（位置/地形/掷骰可见）→ 新态势 → 下一个矛盾
- [ ] 龙王店自带胜负：克据点 / 两部失去战斗力 / 时限未决

### 明确淘汰（避免回到旧范式）

- 原型的静态地图与不动单位；原型的批量抽象 d6 结算（无视位置，被位置结算取代）
- 原型写死的逐回合卡脚本（`cardFor()` 按 turn 分支）——卡从状态派生，这是机制不是剧本
- 帝丘店引擎的逐子微操交互（`clickHex` 玩家点击）降级为执行口子的薄适配器
- 帝丘店引擎的死情报/计划装饰面板——不在此版重建

### 非目标

- LLM 参谋长、情报系统；完整 5 回合史实剧本与全套决心卡（竖切只需 1–2 个矛盾）；三栏界面改造（本版单屏「地图 + 决心卡」）
